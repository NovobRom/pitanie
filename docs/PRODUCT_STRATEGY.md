# Стратегия развития продукта

> Документ описывает анализ текущего состояния приложения (трекер калорий/КБЖУ на
> Next.js 16 + React 19 + Tailwind v4 + Supabase) и план превращения его из «личного
> инструмента» в полноценный мобильный продукт. Философия: **mobile-first + минимализм**
> — берём лучшее у конкурентов, но на экране показываем только необходимое.

Дата: 2026-06-14

---

## 1. Аудит текущего состояния

**Стек:** Next.js 16.1.6 (App Router), React 19, Tailwind CSS v4, Supabase (Postgres 17 + Auth),
lucide-react, деплой на Vercel.

**Что уже работает:**
- Дашборд калорий и БЖУ (кольцо ккал + бары Б/Ж/У, остаток на день).
- Дневник питания с недельным календарём и секциями приёмов (завтрак/обед/ужин/перекусы).
- Поиск продуктов через Open Food Facts (серверный прокси `src/app/api/search-food/route.ts`).
- Авторизация email+пароль (Supabase Auth), синхронизация и шаринг плана по ссылке.
- Калькулятор нормы (BMR/TDEE — Mifflin-St Jeor / Katch-McArdle) в `src/lib/nutrition.ts`.
- i18n на 3 языка (RU/EN/UK) через свой контекст `src/lib/i18n.tsx`.

**Главные проблемы (технический долг):**
1. **Данные хранятся одним JSONB-блобом** в таблице `plans` (ключ `owner_id + дата`). Нет
   истории по продуктам, трендов, аналитики, ссылочной целостности — блоб просто растёт.
2. **Профиль и цели лежат в `auth.users.user_metadata`** — не запрашиваемо SQL-ом, не
   масштабируется, не подходит для продуктовых сценариев.
3. **Нет тестов, CI и мониторинга ошибок.**
4. ~~Сломанная вёрстка экрана логина~~ — **исправлено** (см. раздел 9, Phase 0).
5. ~~Временный/личный брендинг («v4.0 Apple Health Edition», «Роман и Лиза»)~~ — **убрано**.
6. **Безопасность БД** — частично закрыто (см. раздел 5), осталось включить leaked-password
   protection в дашборде.

## 2. Редизайн (направление: iOS-минимализм)

> Стиль чистого минимализма уровня системных приложений здоровья, **без упоминания бренда
> стиля в самом UI**.

**Дизайн-токены**
- Нейтральный светлый фон, крупные мягкие карточки, заметные кольца прогресса (Move-style).
- Тёплая палитра остаётся базой, но повышаем «воздух» и контраст-иерархию.
- Системный шрифт как опция + Inter; полноценный **dark mode** (auto по системе).

**Навигация (минимум кнопок)**
- Нижний таб-бар из **3 пунктов**: **Сегодня · Дневник · Профиль**.
- Единственное primary-действие — крупная кнопка **«+ Записать»** (быстрый лог).
- *Progressive disclosure*: продвинутые настройки (г/кг белка, % жира, формулы) спрятаны
  за «Дополнительно».

**Ключевые экраны**
- **Сегодня (Dashboard):** кольцо ккал + бары Б/Ж/У + остаток; вес-тренд мини-виджет.
- **Дневник:** свайп между днями, секции приёмов, быстрый повтор «как вчера».
- **Быстрый лог:** недавнее/избранное, штрихкод, поиск, ручной ввод — за 2–3 тапа.
- **Профиль:** цели, тренд веса, единицы, язык, подписка.

**Рефакторинг компонентов**
- Переписать `AuthWall`, `Dashboard`, `MealDiary`, `Header` под новую систему.
- Удалить легаси (`CheatSheet`, `DayCard`, `MealCard`, `AuthModal`, неиспользуемые `data/*`).

## 4. Целевая схема БД (скейл/безопасность)

Уйти от одного JSONB-блоба к нормализации **рано** — пока пользователей мало и миграция дешёвая.

| Таблица | Назначение |
|---|---|
| `profiles` | pk = `auth.uid()`; locale, units, sex, birthdate, height, activity, goal_type. Триггер автосоздания при регистрации. **Переносим профиль из `user_metadata`.** |
| `goals` | История целей: `user_id, effective_date, calories, protein, fat, carbs`. |
| `foods` | Кэш-каталог: `source ('off'|'usda'|'custom'), source_ref/barcode (unique), name, brand, per-100g макро+микро (jsonb), verified`. Публичный read, запись сервером, дедуп. |
| `diary_entries` | **Строка на продукт**: `user_id, logged_date, meal_type (enum), food_id, custom_name, grams, снапшот макро, created_at`. Индекс `(user_id, logged_date)`. Включает тренды/аналитику. |
| `weights` | `user_id, date, weight_kg` — тренд + адаптивный TDEE. |
| `recipes` / `recipe_items` | Билдер приёмов (опционально). |
| `shared_links` | Обобщённый шаринг: `token, target, expires_at`. |
| `subscriptions` | Под монетизацию: `user_id, plan, status, stripe_*`. |

**Правила:** RLS на каждой таблице (`owner = auth.uid()`), `updated_at`-триггеры,
`security invoker` во вьюхах.

**Скейл:** Supavisor connection pooling; кэширование ответов Open Food Facts в `foods`;
rate-limit на API-роутах; PITR-бэкапы на платном тарифе; партиционирование `diary_entries`
по дате — позже, при росте.

## 5. Безопасность

**Сделано (миграция `harden_shared_plan_functions`):**
- `create_shared_plan` — `revoke from anon`, доступ только `authenticated` (закрыт спам-вектор
  анонимной вставки).
- Обе SECURITY DEFINER функции — `set search_path = ''` + полная квалификация имён (защита от
  search_path-hijacking).
- `get_shared_plan` остаётся доступной `anon` **намеренно** — это публичное чтение по
  неугадываемому id (enumeration невозможен, RLS на таблице включён).

**Осталось (через дашборд / Management API — не делается через MCP execute_sql):**
- Включить **Leaked Password Protection** (HaveIBeenPwned) + минимальную надёжность пароля.
- Включить **email-подтверждение** для signup.
- Позже: опционально **MFA (TOTP)** — Supabase поддерживает; CAPTCHA/anti-spam на signup.

**Принципы:** RLS-аудит каждой новой public-таблицы; секреты только на сервере (паттерн
`/api/*` уже используется для Open Food Facts — держим так для всех сторонних API).

## 6. Роадмеп + монетизация

**Phase 0 — Гигиена (сделано в этой сессии):** фикс вёрстки логина, фиксы безопасности БД,
чистка брендинга/версии, рабочее имя. Осталось: выбрать имя + домен, включить leaked-password
protection.

**Phase 1 — Фундамент:** новая дизайн-система + mobile-first переписка экранов; нормализация БД
+ `profiles`; сканер штрихкодов; быстрый лог (недавнее/избранное); трекинг веса; PWA.

**Phase 2 — Дифференциация:** адаптивный TDEE; график тренда веса; микронутриенты; билдер
рецептов + генератор под макросы; «копировать день»/шаблоны; dark mode; оффлайн.

**Phase 3 — Рост/монетизация:** подписки (Stripe); AI-логирование (фото/текст через Claude);
интеграции (Google Fit / Health Connect, Apple Health через нативную обёртку); шаринг/соц-функции;
нативная обёртка (Capacitor/Expo).

**Phase 4 — Скейл:** аналитика/коучинг, B2B для диетологов (кабинет клиентов), расширение
локализаций.

**Монетизация (рекомендация):**
- **Freemium + Pro-подписка** (~$5–8/мес или ~$40/год): адаптивный TDEE, микронутриенты,
  безлимит кастомных продуктов/рецептов, AI-лог, экспорт и расширенная аналитика, полная история.
- **Lifetime-тариф** на раннем этапе — для бутстрапа кэша.
- **B2B-тариф** для тренеров/диетологов (кабинет клиентов).
- **Без рекламы** — премиальность согласуется с минимализмом. Аффилиаты (рецепты/продукты)
  — аккуратно и опционально.

## 8. Личные рекомендации

1. Выбрать имя + купить домен `.app`; брендинг версии/стиля уже убран из UI.
2. **Не хранить данные JSONB-блобом** — мигрировать на нормализацию рано (стоимость растёт с базой).
3. Профиль вынести из `user_metadata` в `profiles` с RLS.
4. Сначала **mobile-first PWA**, нативная обёртка (Capacitor) позже — для HealthKit/камеры-штрихкода.
5. **Скорость логирования = главный рычаг ретеншена** → недавнее/избранное/штрихкод/NL в приоритете.
6. Все сторонние вызовы — через серверные `/api/*` (ключи на сервере).
7. Добавить **тесты + CI** (сейчас нет) и мониторинг ошибок (Sentry).
8. **Адаптивный TDEE** — главный отрыв от MyFitnessPal; делать сразу после трекинга веса.
9. UI держать минимальным: **3 таба + один primary «+»**.

## 9. Философия мобайл-минимализма

- Нижняя навигация из 3 пунктов; единственное primary-действие «+ записать».
- Progressive disclosure: продвинутое спрятано.
- Крупные тап-таргеты, свайп между днями, кольца прогресса как ключевая визуализация.
- Опциональный системный шрифт, dark mode, оффлайн-PWA.
- Ноль визуального мусора: «забираем лучшее у конкурентов, но показываем только необходимое».
